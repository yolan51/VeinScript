  written down with reasons (section 5). Disagreeing is welcome; disagree with the stated reason, not with
  the unfamiliarity.

## 1. What VeinScript is

**Identity-Oriented Programming (IOP).** It is an entity-component-system (ECS) language where everything
that happens is an **event**, and behaviour lives in **shards** that react to events or run every frame.
There are no classes.

| Concept | Sigil | What it is | Example |
|---|---|---|---|
| identity | (none) | an id, made by `spawn()` or a builder | `let e = spawn()` |
| shape | `$` | a component: named data fields on identities | `shape $Health { hp: int = 10 }` |
| mark | `#` | a tag on identities (or on shards) | `mark #Enemy` |
| event | `@` | a message: emitted, queued, heard | `event @Damaged { amount: int }` |
| shard | `!` (when referenced) | a unit of behaviour | `shard Combat { hear @Damaged as d { … } }` |
| builder | `&` (when referenced) | a template that makes identities | `builder Unit { $Health  mark #Unit }` |
| qualified path | `*` | a reference into another bundle | `*Vein.Console.Io.@Print` |
| collection | `~` | many of something, as a field with a declared kind | `~<list>`, `~<set>`, `~<ring 8>`, `~<map>` |

- **Organisation.** Code lives in **bundles** (`bundle Game by you { … }`), and a bundle's public API
  sits in **publicators**. An **app** manifest composes bundles, and `need "author.Bundle"` links one
  bundle to another.
- **Queries** walk identities: `target $Position $Velocity #Moving as m { … }`.
- **The commit model.** Structural changes (`attach`, `unattach`, `mark`, `unmark`, `destroy`, `bring`)
  are deferred to the next commit. Field writes are immediate. When several shards write one field in
  the same frame, the field's `folds` reducer (`sum`, `max`, …) reconciles the writes. That's what lets
  independent shards stay order-independent and deterministic.
- **Functions.** `fn` is a pure function that returns a value. `SF` is a "shard function" that acts by
  emitting and never returns a value; you call it with `do name(…)`.
- **Two runtimes.** An interpreter runs the whole language. A C# backend compiles the "identity half",
  about 14–25× faster, and a differential check proves both give the same output. A JIT (`Vein.Jit`,
  through Roslyn) exists too.

### A taste, excerpted from samples that run

Two forces that don't know about each other, reconciled by `folds sum` on `$Velocity`
(`samples/motion.vein`):

```
shard Gravity {
    each tick { target $Velocity #Moving as m { m.Velocity.y -= 4.9 } }
}

shard Wind {
    each tick { target $Velocity #Moving as m { m.Velocity.x += 1.0 } }
}

shard Step {
    each tick {
        target $Position $Velocity #Moving as m {
            m.Position.x += m.Velocity.x * 0.5
            m.Position.y += m.Velocity.y * 0.5
        }
    }
}
```

Three bundles each declare `@Strum` with a different payload. An app needs all three and picks one by
path (`samples/event_strum/`):

```
bundle Guitar by alice {
    publicator Api {
        shared("A guitar string was strummed.")
        event @Strum { note: string, fret: int }
    }
    shard Player {
        hear @Strum as s {                       // bare = THIS bundle's own @Strum
            emit *Vein.Console.Io.@Print { text: "[guitar] heard its own Strum: note " + s.note }
        }
    }
}

bundle Band by you {
    need "alice.Guitar"
    need "bob.Banjo"
    need "carol.Harp" as H                      // an alias: reached as *H.…, adds no bare names
    shard Lead {
        run once {
            emit *alice.Guitar.Api.@Strum { note: "E", fret: 3 }
            emit *H.Api.@Strum { pluck: "C", octave: 4 }
            emit *Banjo.Api.@Strum { course: 9, roll: false }   // shortened: unique, so it is bob's
        }
        hear *bob.Banjo.Api.@Strum as s { … }   // hears bob's Strum only
    }
}
```

**Things that surprise newcomers:**
- No `!=`: write `not (a == b)`. Logic is words, and `!` is the shard sigil.
- No ternary operator, no `->` (a result type follows the word `return`), and no lambdas.
- Statements end at the newline. A continued expression needs a trailing `+`.
- `+` on strings means *append*.
- Some keywords can't be names: `count`, `base`, `settled`, `need`, `code` (in a builder parameter).
- A `bring` is visible from the next event, not the current one (commit per event, RULES 12b).

## 2. Why it's interesting

The claim worth testing is **coherence**: one idea, *identities exchanging events*, carries everything
built so far, without bolting on a second paradigm.

- **The runtime.** An event loop plus a tick loop, with `folds` for concurrent writes.
- **The editor.** The Workbench draws the event flow (`veinc flow`). Completion lists every `@Event` in
  scope with its owner.
- **The network.** `Vein.Net` sends events between processes. Co-op (`net.Coop`) is host-authoritative
  and written in VeinScript.
- **Web.** Pages are rendered from fragments, and `veinc serve` answers HTTP as events.
- **A blockchain (VeinChain).** The rules are VeinScript bundles that every validator runs.
  Determinism is nearly free: queries run in id order, ids are sequential, `random()` is seeded and the
  host owns the clock.
- **Code genetics (VeinDNA).** A bundle's "genome" is its wiring: which shapes, events, shards and
  builders it declares, and who hears what. Wiring is a first-class thing in IOP, so similarity
  between two programs can be measured structurally rather than textually.

A second claim: **silent failure is the enemy.** Nearly every rule in `docs/RULES.md` (about 70 entries,
numbered with sub-letters) was written after something compiled, ran and quietly did nothing. ROADMAP
Tier 1 is called "silent failures made loud".

### History in one paragraph

The plan was transpiler-first, with an interpreter "later". That inverted: the interpreter became the
primary runtime (reactive event loop, consoles, networking, serve, app linking), and the C# backend
arrived last, covering only the half where compiling pays. "Runtime" turned out not to be one thing. A
program is reactive *and* identity-shaped, and those halves want different execution.

## 4. Design decisions (`SYNTAX-DECISIONS.md`)

| # | Decision |
|---|---|
| D1 | Parameters and fields are `name: Type` |
| D2 | The conditional is `if`; `when` is the `match` arm keyword |
| D3 | Iteration is `target`, `repeat`, `while`: no `for`/`in`/`loop` |
| D4 | No `push`: mutation is `+=`, and `folds` reconciles concurrent writes |
| D5 | Pure IOP: no general `class`; behaviour lives only in shards |
| D6 | `fn` for general functions; `SF` marks shard functions |
| D7 | Statements end at the newline |
| D8 | The sigils `$ @ #` are core syntax |
| D9 | Collections and indexing use brackets (partly open) |
| D10 | Generics `<T>`: **open**, low priority |
| D11 | `enum` is declared inside a `shape` |
| D12 | Logic is words: `not (a == b)`, and `!` is not a logic operator |
| D13 | Query order is spawn order; `by Shape.field` sorts it |
| D14 | There are two places to impose an order: the query, and the brings |
| D15 | An SF call says so: `do name(…)`; an `fn` call stays bare |
| D16 | An fn's result type follows the word `return`: no arrows, no lambdas |
| D17 | Reserved for named arguments (open, in ROADMAP Tier 3) |
| D18 | `mute X` pauses a shard by name, from the next commit |
| D19 | `!Name` is the shard sigil; `not` excludes an `audience` entry |
| D20 | A shard's marks are a group: `mute #Gameplay`, `mark !Spammer #Banned` |
| D21 | `tune("doc")` makes a shard var a setting; values live in `vein.settings` |
| D22 | `target $S on e as x` looks at one identity; `each tick as t` binds the clock |
| D23 | `format` · `loom<Format>` · `weave Loom(text)`: identities from a string |
| D24 | `~` collections: `~<list|set|ring N|map>` fields, `.add/.remove/.clear/.has/.put`, `$Shape` elements, `owns` (owned elements are destroyed with their owner or on removal) |

**The working rule for new syntax:** check these decisions and `LANGUAGE.md` first. A proposal that
re-opens one should say why the original reason no longer holds.

## 5. The ecosystem (sibling repos on the same machine)

```
 VeinsScriptFirst ──packs──▶ ~/VeinFeed (local NuGet feed) ──▶ VeinScriptBundle, VeinGodot, VeinChain, VeinDNA
        │                                                             │
        └─ Workbench ── publishes bundles ──▶ ShardStore (Supabase) ◀── veinscript.base44.app (the public site)
                                                   │
                                     VeinDNA sequences them ──▶ BundleDna rows on the site
                                                   │
                                     VeinChain verifies + rewards ──▶ Vein Coin for useful code
```

The rule: **VeinScript stays engine-neutral.** Godot, the chain and the rest live in their own repos and
consume VeinScript only as packages.

- **VeinScriptBundle.** Reusable VeinScript, one package per area:
  - **Vein.Bundles.Core:** timers, save, inventory, loot;
  - **.Game:** cameras, movement, collect, pause, click-move;
  - **.Web:** page, site;
  - **.Rpg:** stats, combat, monsters, levels, equipment, skills;
  - **.Net:** mesh, chat, co-op.

  Its tests are VeinScript programs, run on both runtimes.
- **VeinGodot.** A Godot 4.7 addon: game rules written in VeinScript, running inside Godot in 2D and 3D.
  It includes a 3D demo, a shooter, an action RPG (a crypt) on the Rpg package, two-process network
  co-op, and a starter script for new games.
- **ShardStore and veinscript.base44.app.** A public store of VeinScript bundles in Supabase, with a
  Base44 web front end. The Workbench publishes to it.
  - Many store bundles predate recent language changes (`use` → `need`, `->` → `return`, `do` for SF
    calls) and no longer compile. They are waiting to be republished.
- **VeinDNA** (`Desktop\VeinDNA`). It turns source into a **genome**: genes of kinds shape, event, shard,
  builder, fn and mark, on two strands (named, and structural with names stripped). Each gene has a
  SHA-256 id.
  - **Similarity** is rarity-weighted Jaccard (65% structural, 35% named) plus MinHash.
  - **Verdicts:** DeclaredFork, SameWiringDifferentNames, CloseRelative, SharesParts, Unrelated.
  - **Comparison stats:** how many shapes, events, hears, emits, builders, brings…
  - **Also:** a UPGMA family tree, a CLI (`veindna sequence|compare|relatives|tree|lab|view|rewards|sync`),
    an HTML viewer, and sync to the Base44 site.
- **VeinChain** (`Desktop\VeinChain`). An experimental blockchain whose state is identities (a guild, a
  package, an asset, a person) and whose rules are VeinScript (`rules/chain.vein`, bundles chain.Coin,
  Stake, Identity, Work, Rewards, Market).
  - **Consensus:** Tendermint-style Byzantine-fault-tolerant consensus (BFT), over real TCP between
    validator processes.
  - **"Useful work":** validators verify published VeinScript packages (compile, run their tests,
    sequence their DNA) by commit-reveal, instead of burning computation.
  - **The reward algorithm** (in `VeinDNA/docs/REWARDS.md`, mirrored on chain to the unit):
    - **Value comes in only through endorsement:** someone locks coin behind a package, weighted by
      √(locked).
    - **Adoption:** value flows along `need` (8 rounds, 85% passed on each round).
    - **Copies:** the same genome as an earlier package credits the original.
    - **Forks:** a fork keeps only its originality.
    - **Quality gate:** verified, at least 1 passing test, at least 10 statements.
    - **Cap:** 20% of the pool per author.
    - **All integer math**, so every node pays the same.
  - **First real payout, on a 4-node test network (2026-10-25):**
    - alice published a library;
    - bob published an app that needs it;
    - carol endorsed bob's app with 50 VEIN;
    - at the epoch, alice and bob each earned 59.8 VEIN (the cap held them), and 183.4 VEIN stayed in
      the pool.
  - **Also there:** a market of play-money assets with constant-product pools, a test faucet, and a
    one-click start and stop for a test network.
  - **Legal-first:** Vein Coin never goes beyond test networks without legal counsel.

## 6. Recent work (the last few days, in VeinsScriptFirst)

- **D24 collections:** list, set, ring and map fields; `$Shape` elements; `owns`; map walks with
  `e.key`/`e.value`. The Workbench shows a collection's kind in hovers, inline `‹map›` hints and
  completion.
- **One editor brain:** `EditorService` serves the Workbench and `veinc lsp`. A VS Code extension now
  has completion, hover, go-to-definition, references, the outline, quick fixes, hints and semantic
  colours.
- **The Workbench's DNA and Chain tabs:**
  - **DNA** shows the open bundle's genome, its closest relatives in the store, and stats side by side;
  - **Chain** shows your packages, endorsements and earnings on a VeinChain network.
- **A shared `fn` now runs where it was written** (ROADMAP Tier 1 #4). Imported bodies resolve their bare
  calls against their owner bundle: its siblings, private helpers and the bundles it `need`s. Before,
  library authors had to fully qualify calls to their own code, or the call answered empty.
- **Event paths.**
  - A shortened path (`*Banjo.Api.@Strum`) used to compile and reach nobody. Now it reaches its unique
    owner.
  - A path shortened past unique (`*Api.@Strum`) is now error VS0306, listing every owner.
  - A bare ambiguous `@Strum` warns VS0216 once, at its line, instead of several times at `:0:0`.
  - `samples/event_strum` demonstrates all of this.

## 7. Open work

- **Tier 1, silent failures made loud.** These still fail silently:
  - a misspelt field read through a typed binding;
  - a misspelt payload field in a `hear`;
  - `serve` can read any path (a security issue);
  - a bundle-level `let` is dropped;
  - recursion and loop caps return null quietly;
  - an `fn` that falls off its end returns null;
  - a misspelt `enum` arm never matches.
- **Tier 2, a game host:** a window and input host, so the game half of the language has something
  driving it outside Godot.
- **Tier 3, writing programs:**
  - named arguments (D17);
  - **a helper that both changes the world and answers.** This is the biggest open design question. An
    `fn` answers but can't `bring`/`destroy`; an `SF` acts but can't answer. The candidates are a
    read-only query expression usable in an `fn`, or a reply event;
  - `expect` assertions in VeinScript tests;
  - the rest of the list operations;
  - string building without `+` chains (interpolation `\(expr)`?);
  - multi-line literals.
- **Tier 4, bundles from a catalog:** `veinc add Author.Bundle` from the store, versions plus content
  hashes in `vein.lock`, and an API diff at publish.
- **Tier 5:** `veinc fmt` and `--help`.
- **Tier 6:**
  - `veinc run --compiled` through the JIT;
  - `dataDir`;
  - directory listing;
  - trig and vectors in `Vein.Math`.
- **Still open from the last few days:** overloading builders (the question was "three variants of
  builder `Button`?"), D10 generics, republishing the stale store bundles, and setting up Base44's DNA

## 8. How Yohann works (the agreements behind the code)

- **Features go in VeinScript, not C#.** A language gap gets fixed in the language, and reusable
  behaviour becomes a bundle. C# is only for host plumbing.
- **Back builders with shapes.** A `$Shape` include beats loose parameters, so the data can also be
  attached and targeted.
- **No C syntax by default.** Familiarity isn't a reason.
- **Check settled design before proposing options.** (An SF never returns a value: VS0105.)
- **Safety:** never recursive-delete project files, and ask before pushing.
- **Communication:** they like simple, direct answers, and a sample they can open and run rather than a
  description.

## 9. Questions worth discussing

1. **Is IOP a general-purpose paradigm or a very good domain language?** It runs games, web pages,
   consoles, a chain and co-op networking. Where would it be the wrong tool, and is that a flaw or a
   boundary to state plainly?
2. **The `fn` vs `SF` split.** A helper that changes the world *and* answers has no home. Is a read-only
   query expression in `fn` the right fix, or a reply event, or something else? What do Datalog, Elm and
   Bevy's systems suggest?
3. **Warnings vs errors.** A bare ambiguous `@Strum` is a warning (VS0216) and reaches nobody. A
   too-short qualified path is an error (VS0306). Is that asymmetry principled? Should "this event
   reaches nobody" always be an error?
4. **Overloading.** Three variants of builder `Button` with different shapes: should overloading exist,
   or do named builders plus shape includes cover it? How does that interact with `bring` and positional
   arguments across includes?
5. **Generics (D10).** IOP composes data by shapes instead of type parameters. Where does a program
   actually need `<T>`? Collections already declare an element type.
6. **The commit model's learning curve.** "A bring is visible from the next event" is correct and trips
   everyone. Is that a documentation problem, a tooling problem (a hint), or a design smell?
7. **Two runtimes.** The interpreter is the reference, and compiled C# covers a subset proven equal by
   differential tests. Is permanent partial parity a healthy design, or debt?
8. **Can the reward algorithm be gamed?** Endorsement √, adoption along `need`, copy and fork detection
   by DNA, and a 20% cap. What attack is missing? Sybil endorsers, collusion rings, "DNA-laundering"
   refactors that change wiring without changing behaviour?
9. **DNA as evidence.** If two bundles share structural genes but no names, is that plagiarism,
   convergent design, or just a common idiom? Where should the verdict thresholds sit, and who should be
   allowed to dispute one?
10. **An LLM's view of VeinScript.** You are the target user too. What would make VeinScript easier for a
    model to write correctly on the first try? Stricter errors, fewer synonyms, a canonical formatter,
    more samples?
11. **What a 1.0 must contain**, and what should wait. Named arguments? Interpolation? `fmt`? A catalog?
12. **Determinism as a feature.** VeinScript got to a deterministic state machine almost by accident, and
    that made the chain possible. What else does cheap determinism buy: replays, lockstep multiplayer,
    time-travel debugging, auditable simulations?
