The folder decides the kind

publicators/ is API and shards/ is behaviour, and putting a declaration in the wrong one is VS0321. Both folders are structural: BundleLoader merges everything under them into the bundle, fragments first, so "declared last in the main file runs last" holds across files.

spawn is not a keyword

It is an ordinary built-in function: let e = spawn(). It is the only way to make a bare entity, and bring is the shorthand that does it together with attaching and marking.

There is no !=

! is never lexed at all — it falls through to VS0005 unexpected character. Inequality is not (a == b). The strongest confirmation is in the compiler itself: a Ne token kind exists and the parser and interpreter both handle it, and nothing anywhere produces one.

A bundle on disk

Three folder names are read by the compiler. There are no others — a shapes/ or events/ directory would be invisible.

Combat/
  Combat.vein            the main file — `bundle Combat by alice { … }`
  publicators/
    Shapes.vein          becomes `publicator Shapes` — the FILE names it
    Marks.vein
    Events.vein
    Builders.vein
  shards/
    Boot.vein            behaviour only, or VS0321
  .veinproj              entry, saved runs, stdlib path, cloud link — all optional
  vein.discovery         wildcard discovery policy; `shared` still governs use

MyGame/
  app.vein               `app MyGame { load "…" }` — first load is the principal
  MyGame/                the principal bundle
  bundles/               other people's bundles, a resolution root

The published name

A file's name in the catalogue is its address: author, bundle, then the path inside the bundle. It round-trips, so a pull can rebuild a project that compiles.

// name                                     path it restores to
alice.Combat.vein                        →  Combat.vein
alice.Combat.publicators.Shapes.vein     →  publicators/Shapes.vein
alice.Combat.shards.Boot.vein            →  shards/Boot.vein
alice.MyGame.app.vein                    →  app.vein
alice.Combat.publicators.ui.Panels.vein  →  publicators/ui/Panels.vein

Why the folder segment cannot be dropped

Every bundle the New Project scaffold makes contains shards/Boot.vein. Keyed on the bare filename, publishing a second bundle would overwrite the first's — and report success. And because publicators/ and shards/ decide whether a declaration is API or behaviour, a name that loses the folder is a name nothing can restore into a project that compiles.

What a catalogue could index. Classifying a file by the declarations inside it currently means shard, bridge, bundle, ShardView and publicator. That misses every $Shape, #Mark, @Event, &Builder, fn and SF — and it sees nothing at all in a publicators/ fragment, which carries no bundle header. Indexing the declarations above would answer "has anyone published a $Health?", which is not idle curiosity: two bundles declaring one with different fields is VS0220, and VS0332 once they are linked.

Where the docs are wrong

Everything above was read off the lexer and parser. These are the places docs/KEYWORDS.md and friends will mislead you.

  • "61 keywords" — there are 62. docs/RULES.md has it right.
  • bring, builder, bridge, audience are listed as "reserved, no assigned meaning yet" — all four are fully implemented, with parser cases, AST nodes and their own diagnostics.
  • if and while are marked "not in the lexer yet" — both are, and both parse.
  • random() and count() are documented as callable — both are lexed as keywords, and a call target must be an identifier, so writing either is VS0104. random is reachable only through what chance 30% lowers to.
  • map<K,V> is documented as a type — the type parser accepts only an identifier, so any such annotation is VS0100.
  • sync is listed as a scheduling hint — it is lexed and has no parser case at all. Same for on, mute, unmute, transform.
  • docs/OVERVIEW.md still says "the lexer is the only stage that exists today" — the parser, lowering, interpreter and C# backend are all several hundred to a thousand lines each.
  • Indexing s[i] is described as pending in two docs and one compiler comment. It parses, lowers, interprets and compiles.
